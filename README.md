## التفويض المؤقت والبدلاء — ٨ نوفمبر ٢٠٢٦

قسم `/delegations`: يطلب المدير تفويض فحص أو اعتماد جودة في موقع واحد، أو مراجعة أرشيف في قسم وحد سرية محددين. يقبله البديل من حسابه، وينتهي بانتهاء الفترة أو الإلغاء، مع إعادة فحص مصدر الصلاحية واستقلال المعتمد. يُحفظ المنفذ الفعلي ومصدر سلطته في سجل العملية. لا ينقل عهدًا أو أموالًا أو يغيّر أدوار الحسابات. [دليل الاستخدام والكود والجداول والحدود](docs/DELEGATIONS_AR.md). المرحلة 02 ما زالت منفذة جزئيًا.

## الأرشيف الإداري وصلاحيات الأقسام - ٧ نوفمبر ٢٠٢٦

قسم `/archive` للمدير، وللمستخدمين الذين يمنحهم وصولًا صريحًا. أقسام مستقلة وصلاحيات عرض ومعاينة ورفع وتنزيل وطباعة واعتماد وتدقيق وتصدير، مع حد سرية. تحفظ الإصدارات السابقة ولقطات بياناتها، والاعتماد مستقل عن المنشئ والرافع. النسخ الموقعة الجديدة من محاضر التسليم تُربط تلقائيًا دون نقل الملف أو تغيير المعاملة. ربط السابق يدوي للمدير. [الدليل والحدود](docs/ARCHIVE_AR.md).

لا يمنح إعداد الأقسام صلاحيات لغير المدير، ولا يُستورد محضر سابق أو يُعتمد ملف تلقائيًا أثناء الترقية. توضح `/roadmap` التقدم الجزئي والمتبقي.

- لا تُفرج الترقية عن دفعات قديمة، ولا تنفذ موافقات أو رحلات أو تحويلات تلقائيًا. الأرشيف الإداري الشامل والوظائف المتبقية موزعة على المراحل التالية، ولم تُعلن مكتملة.


## تحديث الإنتاج والمخازن — 4 نوفمبر 2026

دورة المنتج متصلة برقم الدفعة: إنتاج ← مخزن ← عهدة مركبة ← فاتورة عميل وإثبات تسليم. التحويلات الداخلية تبقى معلقة حتى إقرار المستلم المحدد، مع إشعار ومحادثة ومحضر وأرشيف.

اقرأ [دليل الإنتاج والمخازن والتتبع بالعربية](docs/PRODUCTION_AND_SUPPLY_AR.md) لاستخدام الحسابين، وتعريف المواقع والأصناف، وتشغيل الإنتاج وصرف الخام والجودة، وفهم الجداول والخدمات والاستدعاءات والحدود الحالية.

- الإنتاج: `/production`، والمواقع والعهد: `/warehouses`، وتتبع الدفعات: `/traceability`.
- حساب الإنتاج التجريبي: `production_demo`، وأمين المخزن: `store_demo`. كلمة المرور الابتدائية `123456` للحسابات الجديدة فقط؛ لا يعيد Seeder ضبط كلمة مرور موجودة.
- `SupplyDemoSeeder` يجهز الحسابات وموقعَي تجربة وصنفَي ورقيات فقط، دون أرصدة أو موافقات. لا يعيد إسناد المخازن القديمة تلقائيًا.
- الأرصدة السابقة تحفظ كدفعات افتتاحية واضحة المصدر، دون اختلاق أثر تاريخي قبل التفعيل. ربط مواقعها بمسؤولي العهد يتم من المدير.
- صفحة المخازن موحدة؛ الرابط القديم `/inventory` يحول إليها للحسابات المسموح لها، مع تعريف الأصناف والأرصدة الخارجية للإدارة من الصفحة الجديدة.



اسم النظام الظاهر **amrbit** منذ تحديث 22 أكتوبر 2026. مصدر الاسم `APP_NAME` وتستخدمه الواجهات وصفحة الدخول وكشف الطلب. مسارات المشروع وحسابات التجربة تحت الاسم السابق باقية كما هي.

نظام عام لإدارة فرق التوزيع والمبيعات الميدانية، متعدد الشركات. **هذه نسخة تطوير محلية قابلة للتجربة، وليست إطلاق إنتاج مكتملًا.** بيانات المياه والمواد الغذائية أمثلة مصطنعة لقطاعين مختلفين.

## جرّب النسخة

للتجربة من جهاز آخر في الشبكة: `start-amrbit-lan.cmd` يشغّل الخادم على عنوان الشبكة الخاص، و`enable-amrbit-lan.cmd` يحتاج تشغيلًا كمسؤول لإضافة استثناء Windows المحدود. [دليل الشبكة وحدود GPS عبر HTTP](docs/LAN_ACCESS_AR.md).

- المشروع الجديد: `C:\xampp\htdocs\fieldflow-next`.
- افتح `start-fieldflow.cmd`، أو شغّل `scripts/start.ps1` من PowerShell.
- الإدارة: http://127.0.0.1:8090/dashboard . الآجل: http://127.0.0.1:8090/receivables .
- بيانات الدخول التجريبية في `.runtime/demo-access.txt`: المدير `amr`، المحاسبة `sara`، والمناديب بأسمائهم مثل `khalid` و`abdullah`. كلمة مرور حسابات التجربة الحالية `123456`؛ تجهيز البيانات مرة أخرى لا يعيد ضبط كلمة مرور غيّرها المستخدم.
- حسابات شركة مدار المستقلة تحمل اللاحقة `2` مثل `sara2` و`khalid2`. أزيلت عناوين البريد من الحسابات الحالية، والدخول وإنشاء الأعضاء يتمان باسم مستخدم. [فتح قاعدة البيانات وتعديل الحسابات](docs/DATABASE_ACCESS_AR.md).
- مدير العرض عضو في شركتي «شركة رواد الورقيات» و«مدار للمواد الغذائية». جرّب تبديل الشركة من أعلى الصفحة؛ البيانات والأرصدة مستقلة. تغير اسم الشركة الأولى بطلب المستخدم في 22 أكتوبر 2026، مع حفظ معرفها وبياناتها السابقة.
- للتجهيز في هذه البيئة: `scripts/demo.ps1` يطبّق migrations ويضيف بيانات العرض عند غيابها، دون مسح بيانات موجودة. **لا تستخدم migrate:fresh على قاعدة تحتاجها.**

## ما يعمل الآن

تحديث 22 أكتوبر 2026: زر «إضافة مركبة» يعرض بطاقات برسوم توضيحية لثمانية أنواع، تبدأ بالفان والدينا والتريلا، مع اختيار واحد مطلوب دون افتراض نوع تلقائي. الشكل يتبع النوع المحفوظ في الجدول وملف المركبة، ويُستعاد الاختيار عند التعديل. [تفاصيل هذه الدفعة](docs/VEHICLE_TYPES_2026_10_22_AR.md).

تحديث 18 أكتوبر 2026: إدارة أعضاء الفريق من `/team` تشمل الإضافة والتعديل والتعليق والتفعيل، وتغطية مناطق المندوب وصلاحيتي البيع والتحصيل. `/vehicles` يدعم أنواع المركبات وبياناتها وتعديلها، مع دليل سائقين مستقل وسجل تسليم وإرجاع. الرئيسية أصبحت قائمة مراجعة وخطة يوم دون خريطة مكررة، والتقارير تضيف أداء المناديب ووسائل التحصيل. [دليل الاستخدام والقواعد وحدود هذه الدفعة](docs/RESOURCE_ADMINISTRATION_AR.md).

واجهة عربية جديدة للإدارة وواجهة يوم المندوب، وخريطة نقاط ومسارات مع استعراض الزمن وعمر آخر موقع. تخطيط رحلة يدويًا، بدءها وإغلاقها، إثبات زيارة داخل نطاق العميل ثم تسجيل نتيجتها. دليل عملاء ومناطق وسيارات ومنتجات ومستودعات، استلام مخزون وتحويل عهدة، دفتر حركات، طلبات بأسعار يحسبها الخادم، تسليم يخصم المخزون، وسداد نقدي/تحويل/بطاقة.

البيع يدعم كامل المبلغ عند التسليم، سدادًا جزئيًا، وآجلًا. صفحة الآجل تعرض إجمالي السوق ورصيد كل عميل ومندوب والمتأخر عن الاستحقاق. المندوب يرى فواتيره وأرصدة عملائها، والمشرف يرى الإجماليات؛ استلام الأموال مخوّل للمدير والمحاسب والمندوب ضمن نطاقه. مدير الشركة يضبط حد العميل الائتماني مع سبب مسجل؛ التخفيض لا يمسح الدين القائم.

نموذج الطلب يدعم عدة أصناف، ومع كل طلب كشف عربي قابل للطباعة يوضح أسطره وإيصالاته والمدفوع والمتبقي. متابعة الآجل تحفظ نتيجة التواصل ووعد السداد والموعد التالي، دون تغيير الرصيد بسبب الملاحظة.

صفحة عهدة النقد تفصل استلام العميل عن تسليم النقد للحسابات: طلب تسليم، حجز للمراجعة، اعتماد مستلم آخر أو رفض أو إلغاء، وسجل يفسر رصيد كل مستلم. التحويل والبطاقة لا يدخلان النقد المحمول. لا يستطيع صاحب العهدة أو مقدم الطلب اعتماد استلامه بنفسه.

التقارير تحسب الفترة والمندوب والمنطقة من قاعدة البيانات، مع رسوم يومية وأعمار الآجل وتصدير CSV بالفلاتر المطبقة. يوجد سجل عمليات وتحقق من عضوية الشركة على كل طلب، ومعرف UUID يمنع تكرار التسليم أو التحصيل أو التحويل. API جهاز عبر Sanctum برمز ينتهي خلال 7 أيام وقابل للإلغاء، مع تحديد الشركة صراحة في `X-Company-ID`.
