# عقد جهاز المندوب — النسخة المحلية v1

قاعدة العناوين: `http://127.0.0.1:8090/api/v1` على نفس الجهاز. إنتاج أو هاتف حقيقي يحتاج HTTPS وعنوانًا يمكن للجهاز الوصول إليه. الخادم الحالي يستمع إلى loopback فقط ولم تُفتح شبكة Windows أو إعدادات الجدار الناري.

## الدخول وإلغاء الجهاز

`POST /token`:

```json
{"email":"rep1.naba@fieldflow.test","password":"<local-demo-password>","device_name":"Android test device"}
```

يعيد رمزًا خامًا **مرة في رد الدخول**، وانتهاءه بعد 7 أيام، والشركات التي يملك المستخدم عضوية فعالة فيها. المخزن في قاعدة البيانات بصمة الرمز. حد الدخول بحسب الحساب وIP، وبحد أقصى 10 رموز لمستخدم قبل إلغاء أحدها. لا تضع رمزًا أو كلمة مرور في ملفات المصدر أو سجل طلبات العميل.

في كل استدعاء محمي:

```text
Authorization: Bearer <device-token>
X-Company-ID: <active-membership-company-id>
Accept: application/json
Content-Type: application/json
```

`DELETE /token` يلغي الرمز المستخدم وحده. `GET /workspace` يعيد بيانات ضمن الدور والشركة. عضوية ملغاة تُرفض حتى لو لم تنته مدة الرمز. لا يحصل المندوب على طلبات أو دين مندوب آخر.

## إرسال عملية

`POST /operations/{action}` يستعمل نفس خدمة الأعمال المستخدمة في الويب. يحمل `request_id` UUID؛ إعادة نفس المحتوى بنفس المعرف تعيد نتيجة سابقة دون تكرار. تغيّر المحتوى أو المنفذ يرجع 409. الصلاحية الحالية تُفحص على الإعادة أيضًا.

الأفعال الخاصة بالمندوب: `trip.start`, `trip.close`, `visit.checkin`, `visit.finish`, `location.record`, `order.create`, `order.fulfill`, `collection.create`.

مثال نقطة مصطنعة:

```json
{
  "request_id":"0f03a570-95c9-4f7a-94d4-7a97f3772601",
  "trip_id":1,
  "event_id":"86457c1e-6a10-4c54-a3c6-4420145d4b20",
  "latitude":24.78,
  "longitude":46.64,
  "accuracy_m":12,
  "speed_kmh":25,
  "captured_at":"2026-10-13T07:00:00Z"
}
```

الوقت أعلاه مثال وليس نقطة حديثة قابلة للإرسال لاحقًا. المصدر تحدده جهة الدخول (`device` عبر API، `web` عبر الجلسة). API الحالي يقبل نقطة حديثة خلال دقيقتين، مرتبطة برحلة نشطة ومندوبها، ويرفض السابقة لآخر نقطة والقفزة غير المعقولة. **هذا ليس عقد مزامنة تاريخ offline بعد ساعات**؛ endpoint الدفعات وسياسة البيانات المتأخرة مرحلة محددة في خطة الميدان.

أموال الطلبات والتحصيل أعداد صحيحة بالهللة. لا يُرسل العميل أسعارًا موثوقة أو إجماليًا للحساب. `items` عدة أسطر من `product_id` و`quantity`، مع `customer_id`, `representative_id`, `warehouse_id`, `trip_id`, `payment_terms` (`cash/partial/credit`), `due_date` للآجل و`initial_paid_minor` للجزئي. يمثل `cash` كاملًا مستلمًا عند التسليم حاليًا، وليس عملية بنكية متصلة.

## أخطاء مهمة للعميل

| الرد | التصرف |
|---|---|
| 401 | الرمز غير صالح/انتهى؛ اطلب الدخول، ولا تفترض وصول الكتابة |
| 403 | عضوية أو دور أو ملكية أو قدرة رمز غير مخولة؛ لا تكرر بلا تغيير صلاحية |
| 404 | السجل لا يوجد ضمن الشركة المختارة |
| 409 | تعارض UUID/معرف النقطة؛ لا تولد UUID جديدًا لإخفاء التعارض |
| 422 | مدخلات أو انتقال حالة أو دليل موقع أو رصيد غير صالح؛ اعرض السبب |
| 429 | تجاوز المعدل؛ انتظر حسب الرد ثم حاول بنفس معرف العملية |
| انقطاع شبكة | إذا كان الطلب قد وصل، أعده **بنفس UUID** بعد الاتصال |

مهم: لا تخزن نقدًا خامًا أو صورًا أو نقاطًا على هاتف بلا سياسة حماية. لا يوجد تطبيق جاهز يطبق Room/WorkManager والمزامنة في هذا المجلد بعد؛ هذه وثيقة العقد المنفّذ ومحدوديته، وليست ادعاء اختبار خلفية Android.
