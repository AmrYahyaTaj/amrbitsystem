# تشغيل amrbit داخل الشبكة المحلية

بتاريخ 22 أكتوبر 2026 كان عنوان Wi-Fi لجهاز التطوير 192.168.8.160، والشبكة 192.168.8.0/24. الرابط:

http://192.168.8.160:8090/login

## من جهاز آخر

1. اربط الجهازين بنفس الشبكة، وتجنب شبكة الضيوف التي تعزل الأجهزة.
2. على جهاز التطوير، افتح enable-amrbit-lan.cmd بزر الفأرة الأيمن واختر تشغيل كمسؤول. تظهر Firewall ready عند نجاح إضافة الاستثناء. حساب الأداة الحالي غير مسؤول، لذلك لم يستطع إضافته تلقائيًا.
3. افتح start-amrbit-lan.cmd لتشغيل الخادم إذا لم يكن يعمل. اترك نافذته مفتوحة؛ Ctrl+C يوقف مشاركة النظام. يلزم بقاء جهاز التطوير يعمل ومتصلًا.
4. من الجهاز الآخر افتح الرابط الذي تطبعه نافذة التشغيل. المدير amr وكلمة المرور التجريبية 123456. بقية الحسابات بالأسماء المبسطة المحفوظة في ملف التجربة.

إذا تغير عنوان جهازك بعد إعادة الاتصال، سكربت التشغيل يكتشف العنوان الخاص الفعال. أعد تهيئة قاعدة الجدار للعنوان الجديد بعد مراجعتها. عندما توجد أكثر من شبكة خاصة فعالة، حدد عنوانًا صراحة عبر scripts/start-lan.ps1 -ListenAddress.

## النطاق والحدود

- يستمع الخادم إلى عنوان الشبكة الخاص المحدد، وليس 0.0.0.0 أو واجهة WSL. تشغيل localhost السابق مستقل. لا تعديل لإعدادات الراوتر أو تحويل المنافذ.
- استثناء الجدار مقيد ببرنامج PHP المستقل، والمنفذ 8090، وعنوان الاستماع وواجهة الشبكة، وLocalSubnet. يطبق على ملف تعريف الشبكة الحالي فقط. لا يُعطل جدار الحماية أو يغير تصنيف الشبكة. إذا وجدت قاعدة مختلفة بالاسم نفسه يتوقف السكربت للمراجعة.
- وضع التفاصيل APP_DEBUG=false وعنوان APP_URL للشبكة يطبقان على عملية خادم الشبكة فقط. الإعدادات الدائمة والجلسات وHTTPS في المتصفح لم تُضعف. HTTP هنا لتجربة الحسابات والبيانات المصطنعة داخل شبكة موثوقة، وليس نشرًا عامًا.
- المتصفح على جهاز آخر يحتاج HTTPS موثوقًا لتحديد الموقع. لا تتجاوز تحذيرات الشهادات ولا تعطل حماية المتصفح. https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition
- عولج اعتماد النماذج على crypto.randomUUID في HTTP عبر مولد UUID v4 يستخدم getRandomValues. هذه عشوائية آمنة وليست Math.random. https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues
- لا يمكن التأكد من وصول هاتف أو جهاز خارجي بمجرد اختبار الرابط من جهاز الخادم؛ تبقى قواعد الجدار وعزل الراوتر والجهاز الآخر ضمن التحقق النهائي.

مرجع استثناء الجدار المحلي: https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule

## إيقاف الاستثناء

أوقف نافذة خادم الشبكة، ثم إذا أردت إزالة سماح الجدار افتح PowerShell كمسؤول ونفذ:

```powershell
Remove-NetFirewallRule -Name 'amrbit-LAN-8090'
```

هذا يستهدف قاعدة amrbit وحدها، ولا يحذف قواعد مشاريع أخرى.
